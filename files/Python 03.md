### Exercise 0: Command Quest (Список команд)

| Параметр | Значение |
|---|---|
| **Директория** | `ex0/` |
| **Файл** | `ft_command_quest.py` |
| **Разрешено** | `print()`, `len()`, `range()`, методы списков |

#### Что нужно сделать
Создать систему управления **списком игровых команд**. Нужно продемонстрировать все основные операции со списками:
- Создание списка
- Добавление элементов (`append`, `insert`)
- Удаление элементов (`remove`, `pop`)
- Поиск (`index`, `in`)
- Срезы (slicing)
- Сортировка (`sort`, `sorted`)
- Итерация

#### 💡 Подсказки
1. **Списки — мутабельные** (можно менять на месте). Это главное отличие от кортежей
2. `append()` добавляет в конец, `insert(i, elem)` — на позицию `i`
3. `list.sort()` изменяет список **на месте** и возвращает `None`. `sorted(list)` возвращает **новый** список
4. Срезы: `list[1:3]` — элементы с индекса 1 по 2 (не включая 3)

> ⚠️ **Нюанс:** `list.sort()` vs `sorted(list)` — частая ошибка. `sort()` возвращает `None`, поэтому `x = list.sort()` даст `x = None`!

### Exercise 1: Score Cruncher (Обработчик очков — Кортежи)

| Параметр | Значение |
|---|---|
| **Директория** | `ex1/` |
| **Файл** | `ft_score_cruncher.py` |
| **Разрешено** | `print()`, `len()`, `range()`, `min()`, `max()`, `sum()`, `round()`, `sorted()`, методы кортежей |

#### Что нужно сделать
Работать с **кортежами** (tuples) — хранить и анализировать игровые очки:
- Создание кортежей с результатами
- Нахождение min/max/среднего
- Сортировка (через `sorted()`, потому что кортежи иммутабельны)
- Распаковка (unpacking): `a, b, c = my_tuple`

#### 💡 Подсказки
1. **Кортежи неизменяемы** (immutable). Нельзя сделать `tuple[0] = 5`
2. Но можно создать **новый** кортеж: `new_tuple = old_tuple + (new_element,)`
3. Запятая после одного элемента **обязательна**: `single = (42,)` — кортеж, `not_tuple = (42)` — просто число!
4. Кортежи **хэшируемы** (можно использовать как ключи словарей), списки — нет
5. Распаковка: `name, score, level = ("Alice", 100, 5)`

> ⚠️ **Нюанс:** Кортеж из одного элемента: `(42,)` — нужна запятая! Без неё `(42)` — это просто число в скобках.

### Exercise 2: Position Tracker (Трекер позиций — Множества)

| Параметр | Значение |
|---|---|
| **Директория** | `ex2/` |
| **Файл** | `ft_position_tracker.py` |
| **Разрешено** | `print()`, `len()`, методы множеств |

#### Что нужно сделать
Использовать **множества** (sets) для отслеживания уникальных позиций игрока:
- Добавление позиций (`add`)
- Проверка посещённых мест (`in`)
- Операции над множествами: объединение (`|`), пересечение (`&`), разность (`-`)
- Демонстрация уникальности (дубликаты автоматически удаляются)

#### 💡 Подсказки
1. **Множества не имеют порядка** и не допускают дубликатов
2. `set.add(elem)` — добавить, `set.discard(elem)` — удалить (без ошибки если нет)
3. `set1 | set2` — объединение, `set1 & set2` — пересечение, `set1 - set2` — разность
4. Проверка вхождения в множество — **O(1)** (мгновенно), в списке — **O(n)** (медленно)
5. Элементы множества должны быть **хэшируемыми** (нельзя положить список в множество)

> ⚠️ **Нюанс:** Пустое множество создаётся через `set()`, а НЕ `{}`. Фигурные скобки `{}` создают **пустой словарь**!

### Exercise 3: Achievement Hunter (Охотник за достижениями — Словари)

| Параметр | Значение |
|---|---|
| **Директория** | `ex3/` |
| **Файл** | `ft_achievement_hunter.py` |
| **Разрешено** | `print()`, `len()`, методы словарей |

#### Что нужно сделать
Работать со **словарями** (dictionaries) для системы достижений:
- Создание/обновление словаря
- Доступ к значениям (`dict[key]`, `dict.get(key, default)`)
- Итерация по ключам, значениям, парам (`.keys()`, `.values()`, `.items()`)
- Проверка наличия ключа (`in`)

#### 💡 Подсказки
1. `dict[key]` бросит `KeyError` если ключа нет. `dict.get(key, default)` вернёт `default`
2. `dict.items()` возвращает пары `(key, value)` для итерации: `for k, v in dict.items():`
3. `dict.update(other_dict)` — объединение словарей
4. С Python 3.7+ словари **сохраняют порядок вставки**

> ⚠️ **Нюанс:** `dict[key]` vs `dict.get(key)` — используй `get()` когда не уверен, что ключ существует. Это предотвращает `KeyError`.

### Exercise 5: Stream Wizard (Генераторы)

| Параметр | Значение |
|---|---|
| **Директория** | `ex5/` |
| **Файл** | `ft_data_stream.py` |
| **Разрешено** | `next()`, `range()`, `len()`, `print()`, `import typing`, `typing.Generator`, `import random`, `random.*` |

#### Что нужно сделать
Создать систему **генераторов** для потоковой обработки игровых событий:

1. **`gen_event()`** — бесконечный генератор, который при каждом вызове `next()` возвращает случайный кортеж `(player_name, action)` из списков игроков и действий

2. Из main — вызвать `next()` **1000 раз** и вывести все 1000 событий

3. Создать **список из 10 кортежей** через `gen_event()`

4. **`consume_event(event_list)`** — генератор, который случайно выбирает элемент из списка, удаляет его и `yield`-ит, пока список не пуст. Используется через `for event in consume_event(list):`

#### 💡 Подсказки
1. **Генератор** — функция с `yield` вместо `return`. Она «приостанавливается» и помнит состояние
2. Бесконечный генератор:
   ```python
   def gen_event():
       while True:
           yield (random.choice(players), random.choice(actions))
   ```
3. `next(generator)` — получить следующее значение
4. Генератор **не хранит** все значения в памяти — вычисляет по одному (lazy evaluation)
5. `random.choice(list)` — случайный элемент, `random.randint(0, len(list)-1)` — случайный индекс
6. `list.pop(index)` — удалить и вернуть элемент по индексу

> ⚠️ **Нюанс:** Генераторы — это главное оружие Python для работы с **большими данными**. Они не загружают миллионы элементов в память, а генерируют по одному. В реальных системах с 10M+ записей это критически важно.

> ⚠️ **Нюанс:** Type hint для генератора: `typing.Generator[tuple[str, str], None, None]` (yield type, send type, return type).

### Exercise 6: Data Alchemist (Comprehensions)

| Параметр | Значение |
|---|---|
| **Директория** | `ex6/` |
| **Файл** | `ft_data_alchemist.py` |
| **Разрешено** | `import random`, `random.*`, `print()`, `len()`, `sum()`, `round()` |

#### Что нужно сделать
Использовать **list/dict comprehensions** для трансформации данных:

1. Список имён игроков (часть с большой буквы, часть с маленькой)
2. **List comprehension #1:** Все имена с заглавной буквы → `[name.capitalize() for name in players]`
3. **List comprehension #2:** Только имена, которые **уже** с заглавной → `[name for name in players if name[0].isupper()]`
4. **Dict comprehension:** `{name: random.randint(0, 1000) for name in capitalized_list}`
5. **Dict comprehension #2:** Только игроки с очками **выше среднего**

#### Пример вывода
```
Initial list of players: ['Alice', 'bob', 'Charlie', 'dylan', ...]
New list with all names capitalized: ['Alice', 'Bob', 'Charlie', 'Dylan', ...]
New list of capitalized names only: ['Alice', 'Charlie', ...]

Score dict: {'Alice': 263, 'Bob': 666, ...}
Score average is 410.11
High scores: {'Bob': 666, 'Charlie': 907, ...}
```

#### 💡 Подсказки
1. List comprehension: `[выражение for элемент in коллекция if условие]`
2. Dict comprehension: `{ключ: значение for элемент in коллекция if условие}`
3. Среднее: `round(sum(scores.values()) / len(scores), 2)`
4. Фильтрация по значению: `{k: v for k, v in scores.items() if v > average}`
5. Проверка заглавной буквы: `name[0].isupper()` или `name == name.capitalize()`

> ⚠️ **Нюанс:** Каждый comprehension должен быть **на одной строке** (если не превышает лимит длины строки flake8 — 79 символов). Это правило из PDF.

> ⚠️ **Нюанс:** Comprehensions работают также для множеств: `{x for x in range(10)}`.
