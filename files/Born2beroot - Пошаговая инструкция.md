# 🏰 Born2beRoot — Пошаговая инструкция по выполнению

> Это не краткая шпаргалка с требованиями (она уже есть в `Born2beroot.md`), а **полный пошаговый план**: что делать в каком порядке, зачем это нужно, и какие конкретно команды вводить. ОС — **Debian** (рекомендован субъектом для новичков, дальше объясню почему).

## 0. Важно понять до старта

- **Графический интерфейс запрещён категорически.** Ни X.org, ни Wayland, ни что-то похожее — иначе **0 за весь проект**. Работаем только в консоли (TTY внутри VM или по SSH).
- **Debian vs Rocky.** Subject рекомендует Debian новичкам — у него проще пакетный менеджер (`apt`), меньше специфики (не нужно тонко настраивать SELinux/KDump, как на Rocky). На защите обязательно спросят, почему ты выбрал именно эту ОС — сравнение будет ниже, включи его и в README.
- **Снепшоты запрещены в начале каждой оценки.** Разрешено делать снепшот **непосредственно перед** защитой и удалять **сразу после**.
- Всё, что сдаётся в git — это **только** `README.md` и `signature.txt`. Сама VM (файлы `.vdi`) в репозиторий **не** попадает.

## 1. Подготовка окружения

1. Установи **VirtualBox** (на Mac с Apple Silicon — **UTM**, так как VirtualBox там не работает).
2. Скачай **netinst ISO** последней стабильной версии Debian с официального сайта `debian.org` (раздел "Download" → "Small CDs or USB sticks" → архитектура amd64). Именно netinst, а не полный DVD-образ — он тянет пакеты из интернета по мере установки, что и нужно для минимальной системы.

> ⚠️ Почему netinst, а не полный образ? Задание требует **минимальный набор сервисов** — полный DVD-образ поставит массу лишнего софта по умолчанию.

---

## 2. Создание виртуальной машины

В VirtualBox: **New** →
- Type: Linux, Version: Debian (64-bit)
- RAM: 1024 MB (для теста мониторинга/CPU load хватит, можно поставить 2048)
- Диск: **VDI, динамически расширяемый**, минимум 8 ГБ (в примере из subject — 8 ГБ). Не переусердствуй с размером — задание прямо просит "avoid unnecessary disk usage".
- Число процессоров (Settings → System → Processor): выставь **2**, чтобы позже в `monitoring.sh` было что показать в "vCPU" и это выглядело осмысленно (с 1 vCPU тоже пройдёт, но 2 удобнее для проверки).
- **Сеть (Settings → Network):**
  - Adapter 1: **NAT** — даёт VM выход в интернет для `apt`.
  - Чтобы подключаться по SSH с хоста на порт 4242, добавь **Port Forwarding** в настройках NAT: Host port `4242` → Guest port `4242` (или используй второй адаптер в режиме **Host-only**, если хочешь оставаться ближе к тому, как это делают на кампусе — оба варианта рабочие).
- Подключи скачанный ISO как оптический диск (Settings → Storage → Controller: IDE → Empty → выбрать файл ISO).

## 3. Установка Debian с ручной разметкой LVM + шифрование

Запусти VM. В меню загрузчика выбери **Install** (не "Graphical install" — не критично технически, но раз графика запрещена в итоговой системе, привыкай к текстовому режиму сразу).

Шаги мастера установки:

1. Язык, локаль, раскладка клавиатуры — на твой вкус (обычно English/US, чтобы не мучиться с путями и локалями в консоли).
2. **Hostname**: сразу впиши `<твой_логин>42`, например `avagyan42`. Это ключевое требование subject — hostname должен заканчиваться на "42".
3. Domain name — можно оставить пустым.
4. **Root password** — придумай пароль, который **уже сразу** соответствует будущей политике паролей (10+ символов, заглавная, строчная, цифра, не больше 3 одинаковых подряд). Это сэкономит время — не придётся потом его пересоздавать.
5. Создание обычного пользователя — укажи **full name** и **username = твой логин** (например `avagyan`, без "42" в конце — "42" только у hostname). Пароль — тоже сразу по политике.
6. **Разметка диска — самое важное место установки.** Выбери **Manual** (не Guided!), потому что нам нужен явный контроль над LVM и шифрованием:
   - Выдели весь физический диск, создай новую пустую таблицу разделов.
   - Создай раздел **/boot** отдельно, **без шифрования**, ~500 МБ, тип ext4. Это обязательно: загрузчик (GRUB) не умеет читать зашифрованные разделы напрямую, поэтому `/boot` должен остаться "снаружи" шифрования.
   - Оставшееся свободное место оформи как раздел **"physical volume for encryption"** (в мастере Debian это пункт **"Configure encrypted volumes"**).
     - Выбери **"Create encrypted volumes"**, укажи этот раздел, подтверди перезапись случайными данными (можно пропустить для скорости на VM — не критично для учебного проекта) и задай **passphrase для шифрования** (это отдельный пароль, не забудь его — без него диск не расшифруется при загрузке).
   - Внутри получившегося зашифрованного раздела (`sda5_crypt` в примере из subject) настрой **LVM**:
     - **"Configure the Logical Volume Manager"** → создай **volume group** (например `<login>-vg`) на этом зашифрованном разделе.
     - Внутри VG создай минимум **логические тома**:
       - `root` (/) — например 3 ГБ
       - `swap` — например 1 ГБ
       - `home` (/home) — например 3-4 ГБ
     - Это и даёт "минимум 2 зашифрованных раздела через LVM" — на деле у тебя будет несколько LV поверх одного зашифрованного PV, что полностью удовлетворяет требованию (посмотри пример `lsblk` в subject — именно такая структура: `sda5_crypt` → `vg-root`, `vg-swap`, `vg-home`).
   - Вернись в основной мастер разметки, назначь файловые системы каждому LV (ext4 для root и home, swap для swap), примонтируй, подтверди запись изменений на диск.

> ⚠️ **Почему шифрование + LVM вместе?** LVM сам по себе не шифрует данные — он просто гибко объединяет пространство. Шифрование (LUKS, `crypt`) защищает данные "at rest" (если диск физически украдут). Subject требует именно эту связку: сначала LUKS-контейнер, потом LVM поверх него.

7. **Package manager**: когда спросит про network mirror — согласись (нужно для установки пакетов вроде sudo, ufw и т.д. позже).
8. **Popularity contest** — ответь "No" (не обязательно, но лишний трафик/сервис не нужен).
9. **Software selection (tasksel)** — здесь **сними все галочки с desktop-окружений** (GNOME и т.д.) и любых графических задач! Оставь только:
   - **SSH server**
   - **standard system utilities**

   Это прямо реализует требование "graphical interface forbidden" — если оставить Desktop environment, апелляция на защите будет мгновенной (grade 0).
10. Установи **GRUB** на основной диск (`/dev/sda`), подтверди перезагрузку.

После перезагрузки система загрузится, попросит **ввести LUKS-passphrase** (это нормально и обязательно — так и должно быть каждый раз при старте VM), затем — логин/пароль пользователя.

## 4. Первичная настройка после установки

Залогинься под своим пользователем, перейди в root через `su -` (пока `sudo` ещё не настроен) и обнови систему:

```bash
su -
apt update && apt upgrade -y
```

Установим сразу набор пакетов, которые понадобятся дальше:

```bash
apt install sudo ufw libpam-pwquality vim curl -y
```

> `vim`/`curl` — не обязательны по subject, но облегчают жизнь при редактировании файлов и проверке сети. Всё остальное — по делу.

## 5. Настройка sudo

### 5.1. Группы и пользователь

Subject требует, чтобы твой пользователь состоял в группах **`user42`** и **`sudo`**.

```bash
groupadd user42
usermod -aG user42,sudo <твой_логин>
```

Проверка:
```bash
groups <твой_логин>
```

### 5.2. Строгая конфигурация sudo

Создай отдельный файл в `/etc/sudoers.d/` (лучше не трогать сам `/etc/sudoers`, а дописывать в `/etc/sudoers.d/`, чтобы не сломать основной файл — это стандартная безопасная практика):

```bash
visudo -f /etc/sudoers.d/born2beroot
```

Содержимое файла:

```
Defaults        passwd_tries=3
Defaults        badpass_message="Неверный пароль, попробуйте снова."
Defaults        logfile="/var/log/sudo/sudo.log"
Defaults        log_input,log_output
Defaults        requiretty
Defaults        secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin"
```

Разбор каждой строки — зачем она нужна:

| Директива | Зачем |
|---|---|
| `passwd_tries=3` | Ограничивает число попыток ввода пароля тремя (требование subject). |
| `badpass_message` | Кастомное сообщение при ошибке пароля (subject требует "custom message"). |
| `logfile` | Все действия sudo пишутся в лог-файл. |
| `log_input,log_output` | Логируется не только команда, но и то, что было введено/выведено в её ходе. |
| `requiretty` | sudo можно вызвать только из настоящего терминала (TTY) — блокирует запуск sudo из фоновых скриптов/крон-джобов без терминала, что снижает риск скрытых атак. |
| `secure_path` | Ограничивает, из каких директорий sudo будет искать исполняемые файлы — защита от подмены команд через `$PATH`. |

Создай директорию для логов (иначе sudo не сможет туда писать):

```bash
mkdir -p /var/log/sudo
```

Проверь синтаксис файла (важно — `visudo` делает это автоматически при сохранении, но если редактировал вручную):
```bash
visudo -c
```

## 6. SSH на порту 4242, без root-логина

Зачем: по умолчанию SSH слушает 22 порт и разрешает логиниться под root — это два классических вектора атаки (боты сканируют 22-й порт и перебирают root-пароль). Subject просит сместить порт и явно запретить root.

```bash
vim /etc/ssh/sshd_config
```

Найди и измени/добавь строки:
```
Port 4242
PermitRootLogin no
```

Перезапусти сервис:
```bash
systemctl restart ssh
systemctl enable ssh
```

Проверка, что слушает нужный порт:
```bash
ss -tulpn | grep ssh
```

> На защите тебя попросят подключиться по SSH под **новым** пользователем — убедись, что подключение работает: `ssh -p 4242 <login>@<IP_VM>`.

## 7. Firewall (UFW)

Зачем: даже если сервисов мало, firewall — это второй рубеж защиты: если случайно поднимется лишний сервис на другом порту, снаружи он всё равно будет недоступен.

```bash
ufw allow 4242
ufw enable
systemctl enable ufw
```

Проверка:
```bash
ufw status verbose
```
Должно быть: `Status: active`, разрешён только `4242/tcp`.

> ⚠️ Firewall должен быть **активен уже при старте VM** — `systemctl enable ufw` как раз это и гарантирует.

## 8. Политика паролей

Здесь два разных механизма, оба обязательны:

### 8.1. Сроки действия пароля — `/etc/login.defs`

```bash
vim /etc/login.defs
```

Найди и поправь:
```
PASS_MAX_DAYS   30
PASS_MIN_DAYS   2
PASS_WARN_AGE   7
```

Разбор:
- `PASS_MAX_DAYS 30` — пароль "протухает" через 30 дней (subject: "expire every 30 days").
- `PASS_MIN_DAYS 2` — нельзя менять пароль чаще, чем раз в 2 дня (защита от обхода политики "истории паролей" через быструю смену туда-обратно).
- `PASS_WARN_AGE 7` — за 7 дней до истечения пользователь начинает получать предупреждение при логине.

Эти параметры действуют только на **новых/изменённых** пользователей. Чтобы применить их к уже существующим (root и твой пользователь), используй `chage`:

```bash
chage -M 30 -m 2 -W 7 root
chage -M 30 -m 2 -W 7 <твой_логин>
```

### 8.2. Сложность пароля — PAM (`pam_pwquality`)

```bash
vim /etc/pam.d/common-password
```

Найди строку, начинающуюся с `password requisite pam_pwquality.so`, и приведи её примерно к такому виду (в одну строку):

```
password requisite pam_pwquality.so retry=3 minlen=10 ucredit=-1 lcredit=-1 dcredit=-1 maxrepeat=3 reject_username difok=7
```

Разбор параметров:

| Параметр | Требование subject |
|---|---|
| `minlen=10` | пароль не короче 10 символов |
| `ucredit=-1` | обязательно ≥1 заглавная буква |
| `lcredit=-1` | обязательно ≥1 строчная буква |
| `dcredit=-1` | обязательно ≥1 цифра |
| `maxrepeat=3` | не больше 3 одинаковых символов подряд |
| `reject_username` | пароль не должен содержать имя пользователя |
| `difok=7` | минимум 7 новых символов относительно старого пароля |

> ⚠️ **Важно:** правило `difok=7` **не должно применяться к root** (так написано в subject: "The following rule does not apply to the root password" — только про это правило, остальные для root тоже обязательны). На практике `pam_pwquality` применяет `difok` ко всем не-root пользователям автоматически при обычной смене пароля пользователем (root, меняя чужой пароль через `passwd`, не проходит проверку сложности вообще) — так что это в целом соответствует требованию из коробки. На защите будь готов это объяснить.

После настройки политики **обязательно смени все пароли заново** (это отдельно подчёркнуто в subject — старые пароли, заданные во время установки, могли не соответствовать новым правилам):

```bash
passwd root
passwd <твой_логин>
```

## 10. AppArmor

На Debian AppArmor обычно уже установлен и включён по умолчанию. Проверь:

```bash
systemctl status apparmor
aa-status
```

Если не активен:
```bash
apt install apparmor apparmor-utils -y
systemctl enable apparmor
systemctl start apparmor
```

> AppArmor — система **Mandatory Access Control (MAC)**: ограничивает, что каждая конкретная программа может делать в системе (какие файлы читать/писать, какие syscalls вызывать), даже если пользователь, от имени которого она запущена, обладает более широкими правами. На Rocky для той же цели используется **SELinux** — оба должны работать **уже при старте системы**, это подчёркнуто в subject отдельным warning-блоком.

## 11. Скрипт `monitoring.sh`

### 11.1. Что должен выводить скрипт

Ровно 12 пунктов из subject, ни больше, ни меньше по сути (баннер — опционально):

1. Архитектура и версия ядра
2. Число физических процессоров
3. Число виртуальных процессоров
4. Свободная RAM + % использования
5. Свободное дисковое пространство + % использования
6. Загрузка CPU в %
7. Дата/время последней перезагрузки
8. Активен ли LVM
9. Число активных соединений (TCP ESTABLISHED)
10. Число залогиненных пользователей
11. IPv4 и MAC-адрес
12. Число команд, выполненных через sudo

### 11.2. Сам скрипт

```bash
mkdir -p /root/scripts
vim /root/scripts/monitoring.sh
```

```bash
#!/bin/bash

# Архитектура и ядро
architecture=$(uname -a)

# Физические процессоры (уникальные physical id, минимум 1 даже если поле отсутствует)
pcpu=$(grep "physical id" /proc/cpuinfo | sort -u | wc -l)
if [ "$pcpu" -eq 0 ]; then pcpu=1; fi

# Виртуальные процессоры (логические ядра)
vcpu=$(grep -c "^processor" /proc/cpuinfo)

# Память
mem_total=$(free -m | awk '$1=="Mem:"{print $2}')
mem_used=$(free -m | awk '$1=="Mem:"{print $3}')
mem_percent=$(echo "scale=2; $mem_used*100/$mem_total" | bc)

# Диск
disk_total=$(df -BM --total 2>/dev/null | grep total | awk '{print $2}' | sed 's/M//')
disk_used=$(df -BM --total 2>/dev/null | grep total | awk '{print $3}' | sed 's/M//')
disk_percent=$(df -h --total 2>/dev/null | grep total | awk '{print $5}')

# Загрузка CPU
cpu_load=$(top -bn1 | grep "Cpu(s)" | awk '{print $2 + $4}')

# Последняя перезагрузка
last_boot=$(who -b | awk '{print $3" "$4}')

# LVM
lvm_use=$(if [ "$(lsblk | grep -c lvm)" -gt 0 ]; then echo yes; else echo no; fi)

# Активные соединения
tcp_connections=$(ss -ta | grep ESTAB | wc -l)

# Пользователи в системе
users_log=$(who | wc -l)

# Сеть: IP и MAC
ip_address=$(hostname -I | awk '{print $1}')
mac_address=$(ip link | awk '/ether/{print $2}' | head -1)

# Команды sudo
sudo_cmd=$(journalctl _COMM=sudo 2>/dev/null | grep -c COMMAND)
if [ "$sudo_cmd" -eq 0 ] && [ -f /var/log/sudo/sudo.log ]; then
    sudo_cmd=$(grep -c COMMAND /var/log/sudo/sudo.log)
fi

wall "
#Architecture: $architecture
#Physical CPU: $pcpu
#vCPU: $vcpu
#Memory Usage: $mem_used/${mem_total}MB ($mem_percent%)
#Disk Usage: $disk_used/${disk_total}MB ($disk_percent)
#CPU load: $cpu_load%
#Last boot: $last_boot
#LVM use: $lvm_use
#TCP Connections: $tcp_connections ESTABLISHED
#User log: $users_log
#Network: IP $ip_address ($mac_address)
#Sudo: $sudo_cmd cmd
"
```

Комментарий по нескольким неочевидным местам:

- `grep "physical id" /proc/cpuinfo | sort -u | wc -l` — на VM с одним virtual socket это поле может вообще отсутствовать, поэтому добавлена защита `if [ "$pcpu" -eq 0 ]`, чтобы не показывать 0 физических процессоров.
- Для лога sudo используется `/var/log/sudo/sudo.log`, который мы сами настроили директивой `logfile` в шаге 5.2 — без этой настройки команда не найдёт лог и вернёт 0.
- `wall` рассылает сообщение на все открытые терминалы (TTY-сессии) — именно так, как требует subject ("display on all terminals").

Сделай скрипт исполняемым:
```bash
chmod +x /root/scripts/monitoring.sh
```

Проверь вручную:
```bash
/root/scripts/monitoring.sh
```

### 11.3. Запуск каждые 10 минут + при старте — через `cron`

```bash
crontab -e
```

Добавь две строки:
```
@reboot /root/scripts/monitoring.sh
*/10 * * * * /root/scripts/monitoring.sh
```

Разбор:
- `@reboot` — запускает скрипт один раз сразу при старте системы (subject: "At server startup, the script will display...").
- `*/10 * * * *` — запускает каждые 10 минут постоянно.

Убедись, что `cron` сам включён на автозапуск:
```bash
systemctl enable cron
systemctl start cron
```

> На защите попросят **объяснить, как остановить скрипт, не модифицируя его** — правильный ответ: закомментировать/удалить строки в `crontab -e`, либо `systemctl stop cron`. Модифицировать сам файл `monitoring.sh` для этого **нельзя** — так и скажи на защите.

## 14. signature.txt и сдача

1. **Выключи VM** (`shutdown now` изнутри, дождись полной остановки).
2. Найди файл `.vdi` в папке VirtualBox VMs (Linux: `~/VirtualBox VMs/<имя_VM>/`).
3. Получи SHA1-хэш:
```bash
sha1sum <имя_файла>.vdi
```
4. Вставь **только хэш** в файл `signature.txt` в корне репозитория.

> ⚠️ Хэш **меняется** при каждом следующем запуске VM. Перед каждой защитой — либо копируй `.vdi` заново и пересчитывай хэш, либо используй snapshot непосредственно для защиты (создать перед оценкой, удалить сразу после).

> ⚠️ Саму VM **никогда** не коммить в git — только `signature.txt` и `README.md`.
